# API Contract — MVP

Base path: `/api/v1`. JSON request/response bodies. Use consistent error envelopes and OpenAPI generated by FastAPI.

## Common error format
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Architecture document is invalid.",
    "details": []
  }
}
```

## Projects
- `GET /projects` — list local projects.
- `POST /projects` — create project.
- `GET /projects/{project_id}` — retrieve project and architecture.
- `PUT /projects/{project_id}` — update project metadata and architecture.
- `DELETE /projects/{project_id}` — delete after UI confirmation.
- `POST /projects/import` — validate and import an exported JSON document.
- `GET /projects/{project_id}/export` — download portable JSON.

## Resource registry
- `GET /resources/definitions` — list resource definitions and capability flags.
- `GET /resources/definitions/{type}` — get one definition.

## Validation and simulation
- `POST /architectures/validate` — validate an architecture snapshot without saving.
- `POST /simulations` — run a supported simulation.
- `GET /simulations/{run_id}` — retrieve immutable run and trace.
- `POST /simulations/{run_id}/compare` — compare two run IDs or snapshots if supported by implementation.

Example request:
```json
{
  "architecture": { "schemaVersion": 1, "nodes": [], "edges": [] },
  "simulationType": "CONNECTIVITY",
  "sourceResourceId": "ec2-web",
  "destinationResourceId": "rds-main",
  "seed": 123
}
```

## Fault scenarios and labs
- `GET /labs` — list labs with domain/topic filters.
- `GET /labs/{lab_id}` — get lab instructions and public metadata; do not expose hidden answer fields before completion.
- `POST /labs/{lab_id}/start` — create attempt and return starting architecture.
- `POST /labs/attempts/{attempt_id}/actions` — submit an action or configuration change.
- `POST /labs/attempts/{attempt_id}/check` — evaluate checkpoint/rubric.
- `POST /labs/attempts/{attempt_id}/hint` — reveal next available hint.
- `POST /labs/attempts/{attempt_id}/reset` — reset to initial state.
- `POST /labs/attempts/{attempt_id}/complete` — score and return feedback.

## Exam practice
- `GET /questions` — filter by domain, objective, difficulty, and format.
- `POST /exam-sessions` — create a session with selected blueprint.
- `GET /exam-sessions/{session_id}` — retrieve session without exposing unanswered answers.
- `POST /exam-sessions/{session_id}/answers` — submit an answer.
- `POST /exam-sessions/{session_id}/finish` — finish and return score/review.
- `GET /progress/summary` — progress by domain/topic, recent attempts, and suggested review.

## API requirements
- Validate all input with Pydantic.
- Never return correct answers for an active exam session before submission/finish.
- Never execute code from imported projects or lab data.
- Limit request payload size and node/edge counts.
- Return `UNSUPPORTED` for unsupported simulation capabilities.
- Keep endpoints local-only by default; if exposed to a network later, add authentication and CSRF/CORS protections as appropriate.
